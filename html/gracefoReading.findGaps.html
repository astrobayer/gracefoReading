gracefoReading.findGaps

Detect sampling gaps and contiguous segments in an L1B time series.

Syntax

[gaps, stats] = gracefoReading.findGaps(time)
[gaps, stats] = gracefoReading.findGaps(time, Name, Value)

Description

Analyses the epoch spacing of a time series read with gracefoReading.readL1b or readL1bMulti and reports every gap exceeding Tolerance times the nominal sampling interval, together with the contiguous segments between the gaps. Downstream processing - filtering, arc segmentation, differentiation - requires contiguous data, so this moves a routine and error-prone preprocessing step into tested code. All three readL1b time formats are accepted and produce identical results; gap epochs are always reported as MJD and seconds of day.

Input Arguments

NameTypeSizeDescriptionOptionsDefault
timedouble | datetime | int64[N x 2] | [N x 1]Epochs as returned by readL1b: [N x 2] integer MJD and seconds of day, datetime on the GPS time scale, or int64 GPS nanoseconds past 2000-01-01 12:00:00. Must be sorted ascending.
'NominalRate'double1x1Nominal sampling interval in seconds (e.g. 1 for ACT1B, 5 for KBR1B, 2 for LRI1B, 3600 for MAS1B).any positive value, or NaN to estimate the rate as the median of the epoch differencesNaN (estimate from the data)
'Tolerance'double1x1A step dt counts as a gap when dt > Tolerance * NominalRate.any positive value; 1.5 tolerates jitter of half a sampling interval1.5

Output Arguments

NameTypeSizeDescriptionOptionsDefault
gapstable[G x 8]One row per detected gap, variables:
  • indexBefore – double: record index before the gap
  • indexAfter – double: record index after the gap
  • mjdBefore – double: integer MJD of last record
  • secBefore – double: seconds of day of last record
  • mjdAfter – double: integer MJD of next record
  • secAfter – double: seconds of day of next record
  • durationSec – double: gap length in seconds
  • missingRecords – double: round(durationSec/rate) - 1
  • Empty – table: (G = 0) if the series is contiguous.
statsstruct1x1
  • n – double: epochs analysed
  • nominalRate – double: sampling interval used [s]
  • rateEstimated – logical: true if estimated from data
  • numGaps – double: height(gaps)
  • totalMissing – double: sum of missingRecords
  • longestGapSec – double: 0 if no gaps
  • segments – double [G+1 x 2]: first and last record index of each contiguous segment

Accuracy and Limitations

  • Differences are formed relative to the first epoch in double precision. Over a one-day series the resolution is better than 1e-9 s, far below any physically meaningful gap, so the double reduction is harmless even for int64 input.
  • Automatic rate estimation uses the median difference and therefore requires that most steps are nominal; for series dominated by gaps, pass 'NominalRate' explicitly.
  • missingRecords is a count derived from the assumed constant rate, rounded and floored at 1; it is an estimate, not a statement about which epochs the data centre actually intended to deliver.
  • Duplicate epochs (dt = 0) are not gaps and are not reported here; use the monotonicity warning of readL1bMulti.
  • The input must be sorted; unsorted input raises an error rather than being silently sorted, since sorting would break the correspondence to obs.

Examples

automatic rate detection on a KBR1B day (5 s nominal)

[t, kbr] = gracefoReading.readL1b('KBR1B_2020-01-01_Y_04.txt');
[gaps, stats] = gracefoReading.findGaps(t);
fprintf('%d gap(s), %d record(s) missing\n', stats.numGaps, stats.totalMissing);

process each contiguous segment separately

[~, stats] = gracefoReading.findGaps(t, 'NominalRate', 5);
for s = 1:size(stats.segments, 1)
   idx = stats.segments(s,1):stats.segments(s,2);
   processSegment(t(idx,:), kbr(idx,:));
end
