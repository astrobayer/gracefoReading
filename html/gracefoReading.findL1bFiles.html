gracefoReading.findL1bFiles

Locate GRACE-FO L1B files in an archive by product and date.

Syntax

files = gracefoReading.findL1bFiles(archiveRoot, product)
[files, report] = gracefoReading.findL1bFiles(archiveRoot, product, Name, Value)

Description

Searches an archive folder for PO.DAAC-named product files, for example ACT1B_2020-01-03_C_04.txt or the gzipped variant ACT1B_2020-01-03_C_04.txt.gz, sorts them chronologically and reports date coverage including calendar days without a file. Together with readL1bMulti this reduces multi-month batch reading to two lines. Files whose names do not match the PO.DAAC pattern are ignored, and an empty result is returned rather than raised as an error, so the function can be used to probe an archive.

Input Arguments

NameTypeSizeDescriptionOptionsDefault
archiveRootstring | char1x1Folder to search.
Validation: mustBeFolder
productstring1x1Product identifier as it appears at the start of the file name."ACT1B", "ACC1B", "SCA1B", "KBR1B", "LRI1B", "GNV1B", "THR1B", "MAS1B", ... Required, positional
'DateRange'datetime1x2Inclusive date window; order of the two elements is irrelevant. Also defines the span over which missing days are reported.[] (all dates found)
'Satellite'string1x1Satellite letter in the file name."C" | "D" (GRACE-FO 1 and 2), "Y" (dual- satellite products such as KBR1B/LRI1B), "" for any"" (any satellite)
'Release'string1x1Release tag in the file name."04", "03", "04"
'Recursive'logical1x1Search subfolders as well, which suits archives organised by year or month.true | falsetrue

Output Arguments

NameTypeSizeDescriptionOptionsDefault
filesstring[K x 1]Full paths sorted by date and then satellite; empty string array if nothing matches.
reportstruct1x1
  • dates – datetime [K x 1]: date of each file
  • satellites – string [K x 1]: satellite letters
  • firstDate – datetime: NaT if no files
  • lastDate – datetime: NaT if no files
  • missingDates – datetime [D x 1]: calendar days with no file inside [firstDate, lastDate], or inside 'DateRange' when it is given

Accuracy and Limitations

  • Dates come from the file NAME, not from the file content; a misnamed file is placed wrongly. Content dates are available from readL1b via the time output.
  • Only the PO.DAAC naming convention PROD1B_yyyy-MM-dd_S_RR.txt[.gz] is recognized. Archives using other conventions need their own listing; the resulting string array can be passed to readL1bMulti directly.
  • Missing-day detection assumes daily files; it is not meaningful for products delivered at another cadence.
  • Recursive search visits every subfolder of archiveRoot and can be slow on network file systems with very large archives; set 'Recursive' to false when the layout is flat.
  • Duplicates of the same date in different subfolders are all returned; the caller decides which to keep.

Examples

one month of ACT1B for GRACE-FO 1, then read it

files = gracefoReading.findL1bFiles(archive, "ACT1B", ...
   'DateRange', [datetime(2020,1,1) datetime(2020,1,31)], ...
   'Satellite', "C");
[t, acc, aux] = gracefoReading.readL1bMulti(files);

check archive completeness before a long run

[~, rep] = gracefoReading.findL1bFiles(archive, "KBR1B", 'Satellite', "Y");
fprintf('%s .. %s, %d day(s) missing\n', rep.firstDate, rep.lastDate, ...
       numel(rep.missingDates));
