gracefoReading.readItsgProduct

Read a TU Graz (ITSG) satellite orbit product.

Syntax

[time, obs, aux] = gracefoReading.readItsgProduct(fileName)
[time, obs, aux] = gracefoReading.readItsgProduct(fileName, Name, Value)

Description

Reads one operational satellite orbit product published by the Institute of Geodesy, TU Graz, from ftp.tugraz.at/pub/ITSG/satelliteOrbitProducts/, and returns it in the same [time, obs, aux] shape as gracefoReading.readL1b. The products are GROOPS ASCII instrument files, so the parsing is done by gracefoReading.readGroopsInstrument and this function adds what the file itself does not carry.

Two things it adds are not cosmetic:

ZERO-PADDED COLUMNS. The GROOPS ORBIT type always writes nine data columns - position, velocity and acceleration. A kinematicOrbit file carries position only, and its six velocity and acceleration columns are identically zero; a reducedDynamicOrbit file carries position and velocity, and its three acceleration columns are identically zero. Returning those zeros as observations would hand a caller a velocity of exactly 0 m/s for every epoch of a kinematic orbit, which differencing or integrating turns into silent nonsense. OBS therefore holds only the columns the product actually carries; the padding is named in aux.paddingColumns and returned untouched in aux.allColumns. Which columns are carried comes from the product documentation, and is CHECKED against the file: a padding column that is not identically zero raises the paddingNotZero warning rather than being quietly dropped.

FRAME AND TIME SYSTEM. Neither is declared anywhere in these files - no header field, no filename suffix, nothing. They come from the product README instead, which states the frame per product and "All times are GPS times". Because that mapping is keyed on the product, and the product is identified from the file name, aux records not just the answer but how it was reached: aux.frameSource and aux.productSource. An unrecognised product is never given a frame by guesswork - aux.frame stays empty and the productNotRecognised warning fires. The time system is not withheld with it: the README states "All times are GPS times" for the whole product set rather than per product, so aux.timeSystem is 'GPS' either way.

Accuracy and Limitations

  • The frame and the time system are NOT in the file. They are taken from the product README of 2025-10-16 and are therefore only as current as that document; aux.frameSource and aux.timeSystemSource say so rather than presenting them as file content. Verify against the README before a result depends on the frame.
  • The two are not documented the same way and are not treated the same way here. The time system is stated once for the whole product set - "All times are GPS times" - so aux.timeSystem is 'GPS' for every file this function reads, recognised product or not. The frame is stated per product, so an unrecognised product gets no frame at all.
  • Which columns a product carries is likewise documentation, not file content, but it is verified against the data on every read. The reverse is not checked: a column documented as carried that happens to be all zero in one file is not reported, because a genuinely zero observation is legitimate.
  • One file per call. Reading a date range means calling this once per file and concatenating; there is no ITSG counterpart to readL1bMulti or findL1bFiles yet (HANDOVER.md, O-9).
  • No frame rotation and no interpolation are performed, and none are planned here - both are out of scope for this toolbox.
  • neutralDensity is published by the same server but is not in the product table, because no real file was available to read. It parses as a generic GROOPS file and warns productNotRecognised.
  • Epoch tags are exact to 1 ns of what the file prints. The files carry 18 decimals of a day, finer than a nanosecond, so the nanosecond outputs round; at most the first 15 decimals are used (86 ps, see readGroopsInstrument).

Examples

kinematic orbit: three position columns, not nine

[t, pos, aux] = gracefoReading.readItsgProduct( ...
   'GRACEFO-1_kinematicOrbit_2020-01-01.txt');
fprintf('%s in the %s frame (%s)\n', strjoin(aux.obsNames, ', '), ...
   aux.frame, aux.frameSource);

exact epochs of a receiver-clock-corrected kinematic orbit

tns = gracefoReading.readItsgProduct( ...
   'GRACEFO-1_kinematicOrbit_2020-01-01.txt.gz', 'TimeFormat', 'gpsns');
fprintf('sampling is constant: %d\n', numel(unique(diff(tns))) == 1);

a day of orbit and its epoch-wise covariance

[tk, pos] = gracefoReading.readItsgProduct('GRACEFO-1_kinematicOrbit_2020-01-01.txt');
[tc, cov] = gracefoReading.readItsgProduct( ...
   'GRACEFO-1_kinematicOrbitCovariance_2020-01-01.txt');
% cov columns are xx yy zz xy xz yz in m^2, on the same epochs as pos
