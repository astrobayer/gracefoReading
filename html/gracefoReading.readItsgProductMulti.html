gracefoReading.readItsgProductMulti

Read and concatenate several ITSG product files.

Syntax

[time, obs, aux] = gracefoReading.readItsgProductMulti(fileNames)
[time, obs, aux] = gracefoReading.readItsgProductMulti(fileNames, ...
Name, Value)

Description

Calls gracefoReading.readItsgProduct on each file - typically consecutive days of one product from gracefoReading.findItsgFiles - and concatenates the results into one continuous record. It is the ITSG counterpart of gracefoReading.readL1bMulti and follows the same rules.

Three things are refused rather than concatenated, because each would produce a result that looks continuous and is not:

- Files whose observation columns differ. Stacking a kinematic orbit (3 position columns) on a reduced-dynamic one (6) would silently change what column 4 means partway down the matrix. - Files of different products, even when their column counts happen to agree. This is checked first, because it is the most informative thing to say about a bad list.

The reference frame is deliberately NOT checked separately. It is derived from the product, and 'Frame' is forwarded to every file, so equal products already mean equal frames; a frame check here could never fire and would be a promise this function cannot keep.

Epoch order is checked but not enforced: a non-increasing join raises the timeNotMonotonic warning naming the record and the file, because wrong file order and a genuine duplicate day look identical here and only the caller knows which it is.

Accuracy and Limitations

  • aux.allColumns is deliberately absent. Concatenating it would stack the zero padding into a single matrix and invite exactly the reading readItsgProduct exists to prevent. Read a file on its own when the padding is what you want.
  • Nothing is interpolated, resampled or gap-filled, and no frame rotation is applied. A gap between files stays a gap; use gracefoReading.findGaps on the result to find it.
  • The kinematic products are not on a constant sampling by design, so a monotonicity check is the only ordering assertion made. Do not read strict monotonicity as evenly spaced.
  • Memory is the limit on how many days can be joined: every file is parsed in full before concatenation. A year of 10 s orbits is roughly 3 million records.

Examples

a month of kinematic orbits in two lines

files = gracefoReading.findItsgFiles(root, "kinematicOrbit", ...
   'DateRange', [datetime(2020,1,1) datetime(2020,1,31)]);
[t, pos, aux] = gracefoReading.readItsgProductMulti(files);

exact epochs across the join, then look for gaps

tns = gracefoReading.readItsgProductMulti(files, 'TimeFormat', 'gpsns');
gaps = gracefoReading.findGaps(tns);
