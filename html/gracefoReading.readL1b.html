gracefoReading.readL1b

Read one GRACE-FO or classic GRACE Level-1B ASCII product file.

Syntax

[time, obs, aux] = gracefoReading.readL1b(fileName)
[time, obs, aux] = gracefoReading.readL1b(fileName, Name, Value)

Description

Reads any GRACE-FO Level-1B RL04 ASCII product (ACC1B/ACT1B, SCA1B, KBR1B, LRI1B, GNV1B, THR1B, MAS1B, ...). These products share one structure: a YAML header terminated by "# End of YAML header" whose "variables:" list declares every data column in order, followed by whitespace-delimited records. The reader is driven entirely by the file's own header, so no release-dependent column tables are hard-coded.

Handled automatically: - single (gps_time) and split (time_intg + time_frac) time tags with unit-aware fractional scaling, read from each file's own header rather than assumed per product family: microseconds in the real IHK1B/MAS1B/THR1B/TNK1B files, nanoseconds in MAG1B, - bit-string flag columns (qualflg, prod_flag) preserved as character bit patterns and decoded into logical bit matrices, - prod_flag-controlled variable-length records (e.g. MAS1B); absent values are returned as NaN, - gzip-compressed input (.gz), decompressed in memory, - strict row-integrity checking with exact line-number reports, - optional content-hashed caching of parsed results.

Classic GRACE (2002-2017) files, whose headers are "KEY : VALUE" lines terminated by "END OF HEADER", are detected automatically. Because classic headers do not declare their columns, built-in per-product layouts or the 'ColumnNames' option supply them; this path is EXPERIMENTAL and warns on every use (see ACCURACY AND LIMITATIONS).

Accuracy and Limitations

  • Time in the default "mjd" format is a double pair; around MJD 58849 the seconds-of-day double resolves about 2e-11 s, so the L1B time tags are represented without loss at both quantizations in use: microsecond, and the nanosecond tags of MAG1B, which 2e-11 s still resolves about fifty times over. The "gpsns" format is exact integer arithmetic and is the recommended handoff to nanosecond pipelines, since a single double cannot hold 2020-era GPS nanoseconds (~6.3e17 > 2^53) without rounding.
  • Values are converted with str2double, i.e. to the nearest double; the ASCII products carry fewer significant digits than a double, so no precision is lost relative to the file.
  • Quality filtering removes whole records; it does not repair or interpolate. Gaps that result are reported by gracefoReading.findGaps, not by this function.
  • Classic GRACE support is EXPERIMENTAL: the built-in column layouts (ACC1B, SCA1B, KBR1B, GNV1B) are taken from the GRACE Level-1B handbook and have NOT been validated against real classic files; classic qualflg may be decimal rather than an 8-character bit string. Every classic read warns accordingly. Verify against a real file, or pass 'ColumnNames', before scientific use.
  • Binary Level-1B files are not supported (ASCII products only).
  • Caching trusts the SHA-256 content digest; if no JVM is available the digest cannot be computed and the file is parsed normally after a cacheUnavailable warning.

Examples

plain read of one daily accelerometer file

[t, acc, aux] = gracefoReading.readL1b('ACT1B_2020-01-01_C_04.txt');
plot(t(:,2)/3600, acc(:, strcmp(aux.obsNames,'lin_accl_x')));

exact int64 nanoseconds, cached, selective flag filtering

[tns, m, aux] = gracefoReading.readL1b('MAS1B_2020-01-01_C_04.txt', ...
   'TimeFormat', 'gpsns', 'QualityBitMask', [6 7], ...
   'CacheDir', 'l1bcache');

one hour of a gzipped KBR1B file as datetime

[t, kbr] = gracefoReading.readL1b('KBR1B_2020-01-01_Y_04.txt.gz', ...
   'TimeFormat', 'datetime', ...
   'TimeRange', [datetime(2020,1,1,0,0,0), datetime(2020,1,1,1,0,0)]);
