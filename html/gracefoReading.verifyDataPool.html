gracefoReading.verifyDataPool

Verify a data pool against its published checksums.

Syntax

report = gracefoReading.verifyDataPool(poolFolder)
report = gracefoReading.verifyDataPool(poolFolder, Name, Value)
[report, summary] = gracefoReading.verifyDataPool(___)

Description

Checks every file of a local data pool against the checksum its source published, so that a silently truncated download, a half-written copy or a file edited by accident is found before it reaches a processing run rather than after it.

The pool is searched for checksum manifests (see 'Manifests' for the patterns). Each manifest lists file names relative to its own folder, so the MD5 list that ships inside a daily L1B archive and a SHA-256 manifest written beside a month of data are both read where they lie. Every listed file is hashed with the algorithm the manifest's own digest length implies and compared; every file in the pool that no manifest lists is reported as well, because "not checked" and "checked and correct" are different answers and a report that showed only the second would be read as the first.

Each row of the report names the manifest that made the claim, so a mismatch can be taken back to its source. Nothing is repaired, deleted or re-downloaded: the function only reports.

Accuracy and Limitations

  • A pool is only as verified as its manifests. Sources that publish no checksums at all (measured for the ITSG and ZARM products) produce UNLISTED rows, which is the honest answer: those files are unverified, not verified-good.
  • Files are hashed byte for byte, so the cost is one full pass over every listed file. Verifying a multi-gigabyte pool is minutes of disk, not seconds; narrow it with 'Manifests' or by pointing poolFolder at one sub-folder.
  • A manifest entry naming a file outside the pool, or a path that does not exist, is reported MISSING rather than silently dropped.
  • The same file listed by two manifests gives two rows. That is deliberate: two sources claiming different digests for one file is exactly the state a verification should expose.
  • Hashing needs the JVM. Under -nojvm every row is UNREADABLE and hashingUnavailable is raised once; no row is reported OK.
  • The function reports; it never repairs. Deleting or refetching a bad file is a decision for the caller.

Examples

verify the whole pool (DATAPOOL, else the older name)

pool = getenv('DATAPOOL');
if isempty(pool), pool = getenv('READING_DATA_POOL'); end
[rep, sum1] = gracefoReading.verifyDataPool(pool, 'Progress', true);
disp(rep(rep.status ~= "OK", :));
fprintf('%d of %d file(s) verified\n', sum1.numOk, sum1.numChecked);

one month, against the manifest written beside it

m = fullfile(pool, 'GRACEFO', 'L1B', 'RL04', '2020', ...
   'SHA256SUMS_2020-01.txt');
rep = gracefoReading.verifyDataPool(fileparts(m), 'Manifests', m, ...
   'ReportUnlisted', false);

fail a batch job on the first bad file

[~, s] = gracefoReading.verifyDataPool(pool);
assert(s.ok, 'Pool %s failed verification: %d mismatch(es).', ...
   pool, s.numMismatch);
