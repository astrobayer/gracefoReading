gracefoReading.writeGroopsInstrument

Export time and observations as a GROOPS ASCII instrument file.

Syntax

gracefoReading.writeGroopsInstrument(fileName, time, data)
gracefoReading.writeGroopsInstrument(fileName, time, data, Name, Value)

Description

Writes an ASCII instrument file in the GROOPS convention

groops instrument version=<version> <typeCode> <dataColumns> (type/dimension header) <numRecords> (record-count line) <decimalMJD> <data1> <data2> ... (one line per record)

closing the loop from PO.DAAC Level-1B files read with this toolbox to GROOPS-based processing without intermediate scripts. Output always uses Unix line endings (LF) on every platform, so files written on Windows and Linux are byte-identical.

Input Arguments

NameTypeSizeDescriptionOptionsDefault
fileNamestring | char1x1Output path; an existing file is overwritten.
timedouble | datetime[N x 2] | [N x 1]Epochs as returned by gracefoReading.readL1b: integer MJD and seconds of day, or datetime on the GPS time scale. Converted to the decimal MJD that GROOPS expects.
datadouble[N x M]Observation columns to write; M may be zero, which produces a time-only file.
'TypeCode'double1x1GROOPS epoch-type code written as the first integer of the type/dimension header.integer-valued; 0 denotes a generic MISCVALUES-style record, other codes denote typed records (accelerometer, star camera, ...) as defined by the GROOPS release in use0
'Version'double1x1Version tag written on the first line.integer-valued, e.g. 2020012320200123
'Format'string1x1printf format applied to each data value.any valid floating-point conversion, e.g. "%.16e" for full double precision or "%.6f" for compact output"%.16e"

Output Arguments

This function returns no outputs; it works by side effect.

Accuracy and Limitations

  • Time is written as decimal MJD in a single double, as the GROOPS convention requires. Around MJD 58849 a double resolves about 1.3 microseconds, which is adequate for 1 Hz Level-1B products but not for sub-microsecond timing; such applications must not round-trip through decimal MJD. The int64 "gpsns" format of readL1b preserves the full time tag inside MATLAB.
  • Data values are written with 'Format'; the default keeps full double precision, a shorter format silently truncates.
  • The header conventions (version tag, type codes) reflect the documented GROOPS ASCII layout but have NOT been verified against a file produced by a specific GROOPS installation; confirm both before relying on this export in production (see HANDOVER.md, open topics). gracefoReading.readGroopsInstrument reads the format back and makes that check a two-line test.
  • NaN values are written as the platform's printf representation of NaN; GROOPS may not accept them, so filter or fill gaps before export.

Examples

export the three linear accelerations of one day

[t, acc, aux] = gracefoReading.readL1b('ACT1B_2020-01-01_C_04.txt');
gracefoReading.writeGroopsInstrument('act.txt', t, acc(:,1:3));

typed record with compact formatting, then verify

gracefoReading.writeGroopsInstrument('act.txt', t, acc(:,1:3), ...
   'TypeCode', 3, 'Format', "%.9e");
[t2, d2, info] = gracefoReading.readGroopsInstrument('act.txt');
